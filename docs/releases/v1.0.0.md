# v1.0.0: rea-game is out

Reverse-engineer any game, rebuild it in any engine, and prove the rebuild plays the same.

rea-game runs the original game with its clock and random numbers controlled from outside, records the inputs, every random number it draws and the game state after each step, and checks any rebuild against that recording. A rebuild only passes when every recorded state matches and it uses exactly the recorded random numbers.

## In this release

- **Three games, verified:** 2048 (19 cases), Chrome's offline Dino (29 cases) and Canvas Bird (30 cases), 155,453 recorded inputs in all.
- **Three engines:** web ports for all three games, plus Rust and Godot 4.4 ports of 2048, each checked by the same `verify` runner.
- **A check that can fail:** every port was broken on purpose (a constant, a collision offset, a timing gate) to make sure `verify` catches it.
- **Agent skill:** a Claude Code and Codex plugin that runs the loop for you: record, write the behavior spec (`GAME.md`), build the port, verify, and report what it could not cover.
- **CLI:** `list`, `new`, `record`, `verify` and `pack`.

## Try it

```bash
npx rea-game list
npx rea-game verify 2048 --port web
```

In Claude Code:

```text
claude plugin marketplace add erkamyaman/rea-game
claude plugin install rea-game@rea-game
```

Then ask: *"rea this game: <link to an open-source game>, rebuild it in Godot."*

Needs Node 22 or newer. Recording browser games also needs Playwright with Chromium.
